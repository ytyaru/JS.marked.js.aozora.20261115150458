```
// 3連続以上の改行を検知して <br> を出力するカスタム拡張
const multiNewlineExtension = {
  name: 'multiNewline',
  level: 'block', // ブロック要素（段落レベル）として処理
  start(src) {
    // 3連続以上の改行がある位置を探す
    const match = src.match(/\n{3,}/);
    return match ? match.index : undefined;
  },
  tokenizer(src, tokens) {
    // 先頭が3連続以上の改行から始まっている場合にマッチ
    const rule = /^(\n{3,})/;
    const match = rule.exec(src);
    if (match) {
      const newlineCount = match[1].length;
      return {
        type: 'multiNewline',
        raw: match[0],
        // 仕様通り (連続改行数 - 2) 個の <br> を作るための数値を保持
        brCount: newlineCount - 2
      };
    }
  },
  renderer(token) {
    // 指定された数だけ <br> を出力する
    return '<br>'.repeat(token.brCount) + '\n';
  }
};
```

# 1. 検証で判明した事実とセマンティック・ウェブの限界

## p + p { margin-top: 1em; } の挙動について

> 隣接兄弟結合子（+）は「直前に <p> がある <p>」にのみ適用されます。そのため、<p> が連続した時だけ間に 1em の余白が入り、見出しや <br> が挟まった時は余白が二重になりません。

これはセマンティック・ウェブの限界というか、そもそもHTMLが英語圏の文書構造を前提としているというローカル・ルールに基づいている事が問題の原因だ。

世界共通ルールにするならば、各言語における最適な構造があるはずだ。しかし日本語の文書構造である意味段落、形式段落を構造化するマークアップ言語は無い。英語圏には段落が一つしかないから意味段落だの形式段落だのという使い分けがない。なのでそこを`<p>`や`<br>`の配置の仕方で工夫するしかない。つまり意味段落なら`<p>`にそれぞれ分けるし、形式段落なら`<p>`内に`<br>`を配置することでそれっぽく見せる。でもその構造は木構造による意味づけにはなっていない。もし日本語で意味づけするなら以下だ。

````html
<p1>意味段落１</p1>
<p1>意味段落２</p1>
<p1>
<p2>意味段落３中形式段落１</p2>
<p2>意味段落３中形式段落２</p2>
<p2>意味段落３中形式段落３</p2>
</p1>
````

`<p1>`はHTMLの`<p>`と同じ。`<p>`間の余白は通常CSSによって１空白行に見えるサイズの余白となる。

`<p2>`は先頭に全角スペース１字分の余白がある。`<p2>`間には一行分の改行がある。空行はない。

私が日本語の文書構造を作るなら、最低でもこうする。

で、こんなマークアップを一々手書きにするなんて絶対に嫌だ。だから簡易構文を作る。以下のように。

```
意味段落１

意味段落２

意味段落３中形式段落１
意味段落３中形式段落２
意味段落３中形式段落３
```

２連続改行で意味段落を分割する。１改行で形式段落にする。これにて日本語の文書構造を記述する簡易構文とする。

但しここでWeb小説のように、余分な空行を意図して表示し、行間を広げて字がつまりすぎないようにしたり、大量の空白を連続させて、スクロールさせ、何が出てくるのか間を置き、ひっぱる表現を作り込むことがしたい時もある。

そこで段落間改行という概念が登場する。

現状、段落間改行は文字通り段落p同士の間に改行brを1個以上差し込むことで表現している。だがこれはセマンティック・ウェブとしては下策だ。意味としては字が詰まり過ぎぬように、だったり、間を置いてひっぱる意味だったりする。実際それはbrではなくCSSでも可能なはずだし、あるいはスクロールではなくページ遷移だったり、所定時間カウントダウンさせて終わるまで読めないようにする仕組みだったりでも表現できる。

大量のbr要素を入れる。だから何？　それに何の意味が？　改行という以外の意味などない。そもそも意味づけというが、意味って何？　曖昧すぎる。何をしたいか、どう表現するか、そのためにどう実装するか。これを明示するだけだ。つまり表現のパターンを用意する。用意された事だけができる。それを使うか否か。それが全て。そこにどのような意味があるかは、読者がどう解釈するかによって変わり、著者が何を意図していたかと合致するとは限らない。なので意味という言葉それ自体が、もう既に曖昧であり未定義になってしまう。

なので私はセマンティック意味づけという言葉やその意味自体が曖昧なのだから、お前に意味付けなんてできねーよ、としか思えない。意味なんて曖昧な言葉など使うべきでない。何ができるか明記すべきだ。しかしそれをすると機能や用途が限定的になりすぎて汎用性を失う。つまりHTMLは自分に大いなる意味や価値があるという誇大広告としてセマンティック・ウェブという言葉を創作し不当に価値が高いかのように見せかける印象操作をしているのだと私は受け取っている。
