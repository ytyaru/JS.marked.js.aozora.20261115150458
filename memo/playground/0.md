はい、完全に可能です。 iframe の srcdoc 属性を使う方式は、file://（ローカル直開き）と https://（オンライン公開）の両方で全く同じコードがそのまま動作する最適な設計です。
Service Workerを使うツール（Playground Elementsなど）と異なり、ブラウザ標準のDOM操作だけで完結するため、プロトコルの違いによるセキュリティ制限を受けません。

実現するための構成とポイント

1. HTML/CSS/JSを1つの文字列に結合して srcdoc に渡す
エディタで編集されたHTML・CSS・JSをJavaScriptで組み立て、プレビュー用 iframe の srcdoc プロパティに代入します。
2. エディタライブラリもローカル同梱にする（完全オフライン対応）
単なる <textarea> ではなくシンタックスハイライト付きの本格的なエディタにしたい場合、CodeMirror や Ace Editor などのJS/CSSファイルをCDN経由ではなくローカルフォルダに同梱して相対パスで読み込めば、オンライン・オフライン問わず全く同じ見た目と機能で動きます。
3. sandbox 属性で安全性を確保する
オンライン公開時に読者が悪意あるコードや無限ループを実行しても親ページに影響が出ないよう、<iframe sandbox="allow-scripts"> を指定します。

最小構成のサンプルコード（単一HTMLファイル）

以下のコードを playground.html として保存すれば、ローカルでダブルクリックして開いても、HTTPSサーバーにアップロードしても同じように動作します。
html
<!DOCTYPE html>
<html lang="ja">
<head>
<meta charset="UTF-8">
<title>Offline & Online Playground</title>
<style>
  body { display: flex; flex-direction: column; height: 100vh; margin: 0; font-family: sans-serif; }
  .editors { display: flex; height: 45%; border-bottom: 2px solid #ccc; }
  .editor-box { flex: 1; display: flex; flex-direction: column; border-right: 1px solid #ddd; }
  .editor-box label { background: #f0f0f0; padding: 4px 8px; font-size: 12px; font-weight: bold; }
  textarea { flex: 1; border: none; padding: 8px; font-family: monospace; resize: none; outline: none; }
  iframe { flex: 1; border: none; width: 100%; }
</style>
</head>
<body>

<div class="editors">
  <div class="editor-box">
    <label>HTML</label>
    <textarea id="html-code"><h1>Hello Playground</h1>
<button id="btn">クリック</button></textarea>
  </div>
  <div class="editor-box">
    <label>CSS</label>
    <textarea id="css-code">h1 { color: #0066cc; }</textarea>
  </div>
  <div class="editor-box">
    <label>JavaScript</label>
    <textarea id="js-code">document.getElementById('btn').onclick = () => alert('動作しました！');</textarea>
  </div>
</div>

<!-- sandbox="allow-scripts" で親ページを保護しつつJSを実行 -->
<iframe id="preview" sandbox="allow-scripts"></iframe>

<script>
  const htmlInput = document.getElementById('html-code');
  const cssInput = document.getElementById('css-code');
  const jsInput = document.getElementById('js-code');
  const preview = document.getElementById('preview');

  function updatePreview() {
    const source = `
      <!DOCTYPE html>
      <html>
      <head><style>${cssInput.value}</style></head>
      <body>
        ${htmlInput.value}
        <script>${jsInput.value}<\/script>
      </body>
      </html>
    `;
    preview.srcdoc = source;
  }

  // 入力のたびにリアルタイム更新（負荷軽減のため300msのデバウンス処理）
  let timer;
  [htmlInput, cssInput, jsInput].forEach(el => {
    el.addEventListener('input', () => {
      clearTimeout(timer);
      timer = setTimeout(updatePreview, 300);
    });
  });

  // 初回描画
  updatePreview();
</script>

</body>
</html>
コードは注意してご使用ください。

注意点（ハマりやすいポイント）

• </script> タグのエスケープ
テンプレートリテラル内に </script> をそのまま書くと親側のHTMLパーサーがスクリプト終了と誤認するため、上記のサンプルのように <\/script> とバックスラッシュでエスケープする必要があります。
• プレビュー内のリンクやフォーム送信
sandbox="allow-scripts" のみの場合、iframe 内での alert() やフォーム送信はブラウザにブロックされます。必要に応じて sandbox="allow-scripts allow-modals allow-forms" のように権限を追加してください。
• コンソールログの表示
ブラウザの開発者ツールを開かずに画面上に console.log() の結果を出したい場合は、srcdoc 内に console.log を上書きして window.parent.postMessage() で親画面に送る小さなスクリプトを仕込むことで簡単に実装できます。
このプレイグラウンドに追加したい機能はありますか（例：シンタックスハイライト、画面上への console.log 出力、複数記事への埋め込み対応など）？ご希望に合わせてコードを拡張します。
